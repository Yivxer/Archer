复核日期：2026-10-01（北京时间）。这是一次状态审查，不代表下面的建议已经获准实施或完成。

## 判断

Archer 已有相当完整的个人 AI 应用底座；剩余工作主要是运行态迁移、真实体验验收、桌面维护债和发布现场收口。不能按成长计划总览的“Part 10 只剩 thread_resume”判断项目已接近全部完成。

假期建议交付一个**稳定、可恢复、可回归、已安装验收的基础版本**。完整 Runtime v1 要求跨领域权威迁移和至少两周真实使用证据，不能承诺在一个假期内全部完成。

## 假期建议顺序与交付标准

1. **保护现场并统一版本。** 先备份用户数据库与配置，按用途整理已有修改和 evidence 修复；不一次提交全部现场。核实安装版连接配置和数据位置。
2. **证明核心使用可靠。** 在隔离数据中验证对话、审阅记忆、线程恢复、审批、取消和应用重启；完成 J8 的真实召回与停点验收。模型验证只用必要的短请求，并预先说明额度成本。
3. **完成一个 Runtime 权威闭环。** 核对并恢复原失败 Run；窗口达标后由用户人工审查，再实施限定命令的可回滚切换。不能代替用户批准 evidence review。
4. **交付安装基线。** 对最终源码跑相应回归、build、打包、安装和跨重启真实任务。记录版本、提交、数据恢复方法和未完成边界；剩余领域继续 shadow 或原有已验证路径。
5. **建立最小改进入口。** 将实际发现的失败收成脱敏、可人工确认的固定 case；先形成可用的审阅与回归流程，再做自动采收和检索归因。

交付应证明：日常核心路径可用、未授权无副作用、取消/重启不重复写入、失败可定位、数据可恢复、安装版对应明确源码。新功能、全面 UI 重写、自动多 Agent 和主动陪伴扩张都不作为这次基础版本的完成条件。
