## 根因与最小修复

1. 轻量聊天只有压缩 persona，默认检索还会跳过部分自然个人问题，导致原始 SOUL/MEMORY 事实不进入实际 prompt。增加只读、有长度上限的相关段落召回；使用配置中的来源，保留来源行号、日期、否定和待验证语境，排除历史档案/索引。没有将题库写入检索器、添加专用答案或导入测试记忆。
2. 显式 thread ID 未找到 capsule 时会借用全局最近线程。显式线程现在只恢复自己的上下文，缺失时不借用其他线程。
3. capsule 的 `decisions` 含助手历史回复，却被显示成“已确认结论”。改为“历史回复（决定须核对用户确认）”，不重写原数据，不将助手建议冒充用户决定。

`tests/test_persona_recall.py` 保留 13 个脱敏回归，覆盖 simple/full、无关与编造问题、纠正后的旧事实、关闭记忆、来源不可用、缓存变化、长度限制、显式未知线程和未确认建议。既有检索失败降级、跨进程 API 与 80 条长对话回归保留。新文件及 runner Ruff 通过；旧文件诊断与父提交相同，新增诊断为 0；diff check 通过。

来源相关性仍有一个明确失败：一个问题额外带入了不相关的日记流程片段。保留该失败及 4% 指标，没有为了零失败放宽判据。三处事实判据的校正保留了原版本及原因，不把问题未要求的日期当答案必需项，并接受两份权威资料中相同事实的不同表述。
